Participants outlined ICON as a pragmatic, extensible agent-level observability, oversight, and control framework with standardized interfaces and real-time enforcement (distinct from AI NetOps and complemented by audit).

* Participants define ICON as an observability, intervention, and control framework for generic AI agents.
* ICON targets agent nondeterminism with observability, human oversight, and control components.
* Reference architecture envisions multi-vendor standardized interfaces: supervisory controller, enforcement plane, runtime telemetry.
* Hackathon prototypes demonstrated anomaly detection, metric collection, and guardrail-driven allow/deny/require-human outcomes.
* Use cases prioritize network operators, customer-facing AI, and verticals; tooling should stay pragmatic and extensible.
* Participants defined ICON as agent-level governance and runtime intervention, distinct from AINetOps' task-level management.
* ICON focuses on observability, policy enforcement, supervisor and enforcement planes, human-in-the-loop interventions.
* AI NetOps targets task interfaces, closed-loop intent management, and use-case-specific orchestration, separate from ICON.
* AUDIT complements ICON by storing post-event evidence; ICON emphasizes real-time monitoring and on-demand control.
* It has different opinions on where to place interfaces—agents versus gateways/controllers.
